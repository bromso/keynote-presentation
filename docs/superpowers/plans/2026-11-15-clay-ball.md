> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** vgpu installed for agents and the project, and a slowly turning orange clay ball on the Cover and Close pages of `design-loop`, with a PNG fallback.

**Architecture:** One WGSL fragment shader (ray-marched displaced sphere) kept as a string in `slides/design-loop/index.tsx`. A `ClayBall` component shows `assets/clay-ball.png` and overlays a vgpu canvas once the first live frame has drawn. The PNG is rendered once by vgpu in Node from the same shader.

**Tech Stack:** React 19, `@open-slide/core` 2.x, `vgpu` 0.6.x (WebGPU).

**Spec:** `docs/superpowers/specs/2026-11-15-clay-ball-design.md`

## Global Constraints

- `package.json` / `bun.lock` change only by adding `vgpu`. If the install demands `three` or anything else, stop and tell Jonas.
- Do not touch `open-slide.config.ts`, `slides/getting-started/`, or `themes/`.
- Ball: ~200 px, centred on (1380, 240), orange near `#ff4a1c`, matte, transparent surround.
- Marker on pages 5–12 stays a flat disc.
- Commit and push only when Jonas asks, after `bun run build` passes.

## Review Focus

- WebGPU unavailable: the PNG stays, no error on the page.
- Thumbnails / overview / presenter preview: PNG only, no GPU context.
- Leaving the page: animation loop and GPU resources are released.
- `prefers-reduced-motion`: the ball does not turn.
- PNG and live frame line up (no jump on swap).
